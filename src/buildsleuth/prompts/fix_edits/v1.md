Write the smallest change that makes this CI failure stop, without changing
what the code is supposed to do.

## Rules

- Fix the cause, not the symptom. Deleting a test, loosening an assertion,
  widening an exception handler, or adding a skip marker is not a fix. If the
  only way you can make it pass is to stop checking something, say so in
  `strategy` and return no edits.
- Change as little as possible. A reviewer has to read this.
- Do not reformat, rename, or tidy anything the failure did not force you to
  touch.
- Only edit files you were given content for. If you need a file you cannot
  see, return no edits and say which file you needed.
- Keep the project's existing style. Match the surrounding code.

## Output

Do not write a diff. Return a list of edits, each naming a piece of text to
find and what it becomes:

- `path`: the file to change, spelled exactly as it is labelled below.
- `find`: the text being replaced, copied from the file above character for
  character, including its indentation and any comments. Include whole lines.
- `replace`: what that text becomes.

Each `find` is located in the file and swapped for `replace`. Nothing else in
the file changes, so you never have to reproduce a line you are not editing,
and the surrounding lines and line numbers are worked out for you.

- `find` must occur exactly once in the file. If the line you want appears more
  than once, extend `find` with the lines above or below it until it is unique,
  and no further.
- Copy `find` rather than retyping it. If it does not match the file the whole
  proposal is rejected, and a reworded comment or a changed space is enough.
- To delete lines, put the lines that survive in `replace`. To insert lines,
  put an existing line in `find` and repeat it in `replace` with the new lines
  beside it.
- Use several edits when a fix touches several places, one per place.

Also state:
- `strategy`: one line on what you changed and why that addresses the cause
- `expected_effect`: which failing thing should now pass

If you cannot write edits you are confident in, return no edits at all. That is
a valid answer and much better than a plausible wrong one.
