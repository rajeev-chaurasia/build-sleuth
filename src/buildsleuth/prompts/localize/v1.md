You have already classified why a CI run failed. Now name the files a person
would have to edit to fix it.

## What counts as a culprit

The file that must change for the failure to stop. Not the file where the
error surfaced, if that file is only reporting someone else's problem.

- A traceback usually names several files. The culprit is normally the deepest
  frame inside this repository, not the library frame above it and not the test
  harness below it.
- If a checker names the remedy directly, for example a word list or a config
  file to update, that file is the culprit.
- If the fix belongs in the workflow definition, name the workflow file.
- If the fix is a file that does not exist yet, return an empty list. A file
  that must be created has no path to blame.
- If the failure is infrastructure, a flake, or otherwise has no source cause,
  return an empty list.

An empty list is a real answer and is often the correct one. Do not pad the
list to look thorough. A wrong path costs more than a missing one, because
someone will go and read it.

## Ranking

Order by confidence, most likely first, at most five. Give each one a short
reason grounded in the evidence you were given, not in general knowledge about
how projects like this are usually laid out.
